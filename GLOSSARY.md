# Glossary
Every term defined on screen in the course, with the chapter that introduces it.

| Term | Meaning | Chapter |
|---|---|---|
| accurate | Everything stated is true to the source | 2.1 |
| AI use policy | Your organization's rules for which AI tools may be used, for what, with which data, and who reviews the results | 6.3 |
| anonymize | Replace or remove everything that identifies a person, so the data can't be traced back to them | 6.2 |
| bottleneck | The step that slows the whole process down, so fixing it speeds up everything after it | 4.2 |
| Claude Certified Associate | Someone who can apply Claude to business and productivity tasks with minimal guidance, and knows when to escalate | E1 |
| complete | Nothing that matters is missing | 2.1 |
| connector | A secure link that lets Claude read, and sometimes act in, an app you use, like Google Drive or Gmail | 5.2 |
| context bleed | When details from one topic leak into work on another, because they share a chat or a memory | 3.4 |
| context window | Everything Claude can see while it writes the next reply, measured in tokens | F2 |
| Cowork | Claude carrying out a multi-step task on files for you, with a plan you can watch and a result you check | 4.4 |
| effort | How much thinking Claude does before answering. Higher effort: slower, more careful | F7 |
| extended thinking | Letting Claude reason for longer before answering. Helps hard analysis, slows simple tasks | 1.4 |
| hallucination | When a model states something false or made up as if it were true | F4 |
| human in the loop | A named person reviews or approves Claude's work before it takes effect | 2.4 |
| incognito chat | A chat that isn't saved to your history or memory. Good for one-off or sensitive questions | F3 |
| iterating | Improving a result in rounds, changing one thing at a time and checking what changed | 1.3 |
| knowledge cutoff | The date up to which a model's training text goes. Later events aren't in what it learned | F5 |
| language model | A program trained on huge amounts of text to predict what comes next, one small piece at a time | F1 |
| multiple response | A question with more than one right answer. It always says how many to pick, like 'Select TWO' | X1 |
| personal data | Any information that identifies a person, or could be linked back to them: names, emails, phone numbers, IDs, and things like health needs tied to a name | 6.2 |
| project instructions | Standing directions that apply to every chat in the project | 5.1 |
| project knowledge | Files you upload so every chat in the project can draw on them | 5.1 |
| prompt | Everything you give Claude to do a task: the request, the background, and how you'll judge the result | 1.1 |
| prompt chaining | Doing those steps one after another, feeding each result into the next prompt | 1.2 |
| requirements | What a piece of work must do, what would be nice, and what's still unknown, written down before you start | 4.1 |
| scaled score | Your result converted to a scale from 100 to 1,000, so every version of the test is judged on the same standard | E3 |
| Skill | A saved set of instructions, and sometimes files, that Claude loads when a task calls for it, like a house style for proposals | 3.1 |
| stakeholder | Anyone who has a say in, or is affected by, a decision, like a manager, a client or a team | 4.5 |
| stale knowledge | A file in the project that was right once and isn't any more | 5.4 |
| structured data | Information in a fixed shape, like rows and columns, that other tools can read: tables, CSV, JSON | 2.6 |
| task decomposition | Breaking a big job into smaller steps that can each be done and checked | 1.2 |
| token | A small chunk of text, often a short word or part of a word. Around 100 tokens ≈ 75 English words | F2 |
| transparency | Being open about when and how AI was used, so people can judge the work | 6.4 |
