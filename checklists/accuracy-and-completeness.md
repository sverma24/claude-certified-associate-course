# Checking an output: accuracy and completeness (Domain 2)

Write the criteria **before** you read the output. Then tick each line.

## Before you read
- [ ] What must this output include? (For a quote summary: price including service, deposit, cancellation terms, minimums, dietary promises, anything that blocks the plan.)
- [ ] Who will read it, and what decision does it support?

## While you check
- [ ] **Accurate:** every name, date, number and quote matches the source.
- [ ] **Complete:** nothing on your list is missing.
- [ ] **"Not stated" is said out loud.** If the source doesn't give a figure, the output says so. Silence reads as "none".
- [ ] **Specific details are traced:** citations, statistics, clause numbers and names come from a source you can open.
- [ ] **Numbers are recomputed** with code execution or by hand, from the source's inputs.
- [ ] **Answers that disagree** are settled by the source, not by picking one.
- [ ] **Wording about people** is checked for bias (age, gender, background).

## Not a check
- Asking Claude "are you sure?" or to mark its own work. It can catch slips, but it isn't verification.
