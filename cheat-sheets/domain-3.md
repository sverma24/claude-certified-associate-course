# Domain 3: Product and model selection (12%)

Claude Certified Associate Foundations course · cheat sheet

## 3.1 Choosing the right feature for the job

Pick the feature by the job. Chat for one-offs, projects for ongoing work, search and Research for what's out there, artifacts for things you keep, code for exact numbers, Skills for routines, and Cowork for files on your computer.
Avoid: 1. Research for a quick lookup · 2. maths in plain chat instead of code · 3. re-pasting the same background into new chats

## 3.2 What each model is built for

Haiku for fast and simple at volume, Sonnet for most work, Opus for complex and high stakes. Effort is a second dial on the same triangle.
Avoid: 1. one model for everything · 2. 'biggest is always safest' · 3. 'smallest is always cheapest', even when errors are costly

## 3.3 Matching the model to the task

Small models for simple work at volume, big models for judgment. A bigger model adds insight, not certainty, so dates and money still get a human check.
Avoid: 1. paying for Opus on a batch of FAQs · 2. trusting the big model's dates without checking · 3. judging a model on one run

## 3.4 Context limits and memory: restart, summarize or persist

Long chats lose track and bleed. Restart for new topics, summarize to carry work forward, and persist the facts every chat needs.
Avoid: 1. one endless chat for everything · 2. a summary that adds things never agreed · 3. personal and client work sharing one memory
